# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**Nine** is a mobile number-puzzle game built with Expo (React Native). The player dials a grid of digits — nine of them, on the dial every shipped mode is played on — to match target sums; modes (Trainee / Accuracy / Speed, plus Arcade behind a flag) and difficulties add scoring, lives, and streak mechanics.

A mode is a value, not a branch: `modes/` holds one file per mode and resolves each into the rules a run is governed by, so the engine never names one. That is what makes room for **challenges** — custom modes on the app for a day at a time, each free to change the dial, the clock, how targets arrive, the scoring and the lives.

## Domain language

The words below are how we talk about the app. Use them in conversation, comments and commit messages. Several differ from the identifiers in the code — the **Code** column is where each one actually lives, so a name in this table always resolves to something real.

### Screens

A **screen** is a full-viewport view. The app has a single route (`app/(tabs)/index.tsx`); every screen except the game itself is a `<Screen overlay>` stacked over it, so "screen" never means "route".

| Screen          | What it is                                                                                                       | Code                                                                       |
| --------------- | ---------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| **splash**      | The logo animation on cold start, before anything else. Outside the game machine.                                | `components/splash-screen.tsx`, gated by `splashDone` in `app/_layout.tsx` |
| **intro**       | The start screen: Alone / With friends, mode, difficulty, PLAY GAME, HOW TO PLAY. Where HOME on game over leads. | machine state `menu`, `components/overlays/menu-overlay.tsx`               |
| **game**        | A live run — dial, targets, top bar, best-scores strip. The only screen that is not an overlay.                  | machine state `playing`, rendered by `app/(tabs)/index.tsx`                |
| **tutorial**    | The game screen playing the tutorial run — the same screen, stripped. Not a screen of its own.                   | `tutorial` on the machine's context, `constants/tutorial.ts`               |
| **pause**       | Mid-run: CONTINUE / END RUN, run stats, high scores, OPTIONS and SHARE.                                          | machine state `paused`, `components/overlays/paused-overlay.tsx`           |
| **game over**   | End of a run: score, run stats, high scores, PLAY AGAIN / challenge / HOME.                                      | machine state `gameOver`, `game-over-overlay.tsx` (+ `game-over-sequence`) |
| **options**     | Display and advanced settings. Reachable from both intro and pause.                                              | `menuOverlay === 'advanced'`, `advanced-options-overlay.tsx`               |
| **how to play** | The player-facing guide. Keep it current — see Rules.                                                            | `menuOverlay === 'howToPlay'`, `how-to-play-overlay.tsx`                   |

### Multiplayer

| Term                    | What it is                                                                                           | Code                                                                  |
| ----------------------- | ---------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| **multiplayer intro**   | Not its own screen: the With friends tab of the intro, where you CREATE GAME or type a code to join. | `playMode === 'friends'` in `menu-overlay.tsx`, `game-code-input.tsx` |
| **waiting room**        | The room before the start: player tiles, the code to share, host starts the game.                    | phase `waiting`, `multiplayer-waiting.tsx`                            |
| **multiplayer game**    | The shared live run.                                                                                 | phase `playing`, `multiplayer-game.tsx`                               |
| **multiplayer results** | Final scores after a shared run.                                                                     | phase `results`, `multiplayer-game-over.tsx`                          |
| **host**                | The player who created the room — starts the game, owns its lifecycle.                               | **called `admin` in code and DB**: `admin_id`, `isAdmin`              |
| **guest**               | Anyone who joined by code. There is no `isGuest`; a guest is `!isAdmin`.                             | `hooks/use-multiplayer-room.ts`                                       |

Two naming traps here: `multiplayer-menu.tsx` is **not** the multiplayer intro — it is the multiplayer _pause_ screen (CONTINUE / LEAVE mid-game). And `host`/`guest` are our words; the code and the Supabase schema say `admin`. Don't rename either without a deliberate pass.

A third trap, newer: that room `admin` — `rooms.admin_id`, `isAdmin` — has nothing to do with the **role** `admin` on `profiles`. One says who started a room; the other says what the app may show a person. Never read one off the other.

A fourth, about a mode: the player reads **ADVENTURE** (Czech **VÝPRAVA**) where the code says `arcade` — the mode id, the `arcade` feature key, `machines/arcade.ts`, `use-arcade-run.ts` and every `Arcade*` identifier. The player-facing name changed and the code word did not, the same split host/guest runs over `admin`.

### Other key words

| Term              | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **mode**          | What a run asks for. One file per mode in `modes/definitions/`, collected by `modes/registry.ts`; `Mode` is the union of the three the game machine runs, `ModeId` is any mode by name — arcade, or a challenge whose id nobody wrote down at build time. Not `PlayMode` (alone / friends) and not `MultiMode` (the two scored modes only).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **difficulty**    | Easy / Hard / Extreme — `Difficulty` in `modes/difficulty.ts`. Orthogonal to the mode, and a mode may pin its own rung (`fixedDifficulty`) and so show no difficulty row at all.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| **run**           | One game from start to game over. "END RUN", "run stats", "this run" — never "round" or "session". That last exclusion is about naming a _game_: a **session** is the window a challenge is planned for, which is a different thing and has its own row below.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **board**         | One mode × difficulty pairing, i.e. one leaderboard. Careful: the How to Play copy uses "board" for the 3×3 playfield — call that the **grid** in code and comments, and the keys themselves the **dial**. Nothing describing the keys is ever called a board; that is what `DialSpec` is for.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **reign**         | One unbroken stretch of a player holding a board — the board, the day it began, and the day it ended or null while it is still theirs. Not only the all-time board: a **day** and a **week** are reigns too, derived on read from `daily_scores` and collapsed so consecutive wins read as the one stretch they were. `Reign` and `heldBoards` in `lib/player-profile.ts`, MEDALS HELD, EVER on the profile. Only `ever` is stored (`board_reigns`), and only an `ever` reign can be open. Distinct from a **medal**, which is a standing right now rather than a span, and from a **record**, which is a moment.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| **fortune**       | What a career comes to: every point the player has ever scored, weighted by the difficulty it was scored on, plus every winning they have **accepted**. It only ever grows — so never a "rating", a "rank" or a "standing", none of which this is. FORTUNE on screen (Czech JMĚNÍ); `Lifetime.fortune` and `fortuneOf` in code. Distinct from **score**, which is what one run was worth and what the per-board table still adds up to.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| **podium**        | The three places a closed window pays: first, second and third, at 1, ½ and ⅒ of that window’s gold, each reckoned on the player’s own score. `WIN_RANKS` and `PODIUM_SHARE` in `lib/winnings.ts`; the code says rank 1, 2, 3 and the player reads gold, silver and bronze. Not a **medal**, which is a standing on a board still open and can be taken back tomorrow — a podium is settled the moment its window shuts and is paid once.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **paid through**  | The last day a player’s winnings are in their fortune. One date per player, `winnings_paid.paid_through`, and the whole boundary of the thing: the fortune counts windows up to it, the launch offers windows after it. Moves forward only, and only when the player accepts. Beside it sits `podium_from`, the first day ranks two and three pay for — set once, never moved, which is what kept every fortune still when the podium arrived.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **accept**        | What a player does to turn winnings into fortune: the press on the launch popup’s own button. **The code word, not the player’s** — `accept_winnings`, `useWinnings().accept`, `accepted` on the card — because the button itself reads **CLAIM** (Czech **VYZVEDNOUT**) and carries no figure, the card beside it having already printed one. That split is deliberate and runs the same way as host/guest over `admin`: `claim` may not name a thing in code, where `toMedals` has meant a medal standing by it since long before winnings existed. Never "collect" or "redeem", neither of which anything says. An unaccepted reward is not lost: nothing but accepting moves the watermark, so the next launch offers it again.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **tutorial**      | The run a first launch offers, on a card over the intro: Trainee with its clock, its cadence and its options taken off — one target at a time, no countdown, the weight on each key and nothing else. A **submode**, not a mode: `mode` stays `trainee` and `tutorial` on the run says which it is, so it is never a `Mode` and never appears on the intro — but it is what the player is shown, via `runLabel`, on the game screen and the pause badge. Also dealt by TRY IT at the end of How to Play. Its rules are a `RulesPatch` in `modes/definitions/tutorial.ts`; the lesson's own numbers stay in `constants/tutorial.ts`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **lesson**        | The script that runs over a tutorial run: six fixed boards, each dealt so that one move is the obvious answer. A card names the target, a card names the sum, the first route is walked one lit key at a time with the rest of the dial dead, then comes a board apiece for the swipe down, the swipe left and the swipe right, a board asking for three of them in a line so that one drag answers it better than three gestures, and a sign-off. Boards in `TUTORIAL_TARGETS`, steps and order in `machines/tutorial-lesson.ts`, driven by `hooks/use-tutorial-lesson.ts`. A **step** is one beat of it — not a screen and not a mode.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| **motto**         | The one line a player writes about themselves, under their nickname on their profile. At most 50 characters. `profiles.motto`, `lib/motto.ts`, `profile-motto.tsx`. Not a "claim" — that word already means a medal standing (`toMedals` keeps a player's best claim per mode).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **role**          | A named stack of features, held on `profiles.role` as a foreign key into the `roles` table: null for an ordinary player, which is all but a handful of rows. **Flat** — roles are not ranked and none inherits from another, so `admin`'s stack is spelled out in full. Created, renamed and deleted from the admin screen rather than set by hand in SQL. Never a permission: it decides what a player is _shown_, not what a player may do. Not the multiplayer host, who is also called `admin` — see the trap above.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| **rules**         | Everything a live run is governed by, as one value: the dial under it, the clock and what tightens, how targets arrive, the blend a hit is scored by, the lives, and the capability flags. `RunRules` in `modes/rules.ts`, resolved by `runRules(mode, difficulty, tutorial)`. The engine reads these and names no mode, so a mode it has never heard of runs correctly. A mode's own half of it, before a difficulty is applied, is `TargetRules`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **dial**          | The keys a run is played on: how many, how they are arranged, what each multiplies its digit by, and how far a digit goes. `DialSpec` in `modes/dial.ts`; the one every shipped mode uses is `NINE_DIAL`. A **grid** is one position of it — a flat, row-major list of digits, so nothing holding one has to know the shape it is drawn in. Never call either a "board".                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| **capability**    | What a mode is _shown as_ rather than what it is scored by: `board` (keeps a mode × difficulty leaderboard, with its periods, medals and reigns), `scored` (the run has a figure worth showing and counting), `coached` (teaches), `keyHints` (the dial may print what a key is worth), plus `usesDifficulty`. Each one replaces a `mode === 'trainee'` that used to live in the screen it affected — ask `traitsOf(mode)` or the run's rules, never the mode's name. The first two were one flag until challenges needed both answers at once: a challenge is `scored` and keeps no `board`, forced by `defineChallenge`. Practice answers no to both.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| **challenge**     | A mode that is on the app for a window and then is not — twenty-odd of them, each a day long. Not a special case in the engine: `defineChallenge` (`modes/challenges/define.ts`) turns a spec into an ordinary mode definition with a `window` on it, and the registry holds it beside the permanent ones. Careful: `Challenge` in `lib/next-challenge.ts` is the _dare_ the game-over screen offers — the same run one rung harder — and has nothing to do with these.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| **session**       | One planned appearance of a **challenge**: one challenge, one start, one end, one row. The admin's booking, made on the CHALLENGES half of the admin screen — so when a challenge is on is a row rather than two timestamps in the bundle. `challenge_sessions` in the database, `AdminSession` in `lib/admin/sessions.ts`, the arithmetic in `lib/challenge-session.ts`. **Not a run** — see the exclusion on that row, which is about calling a _game_ one — and not a **window**, which is still the `from`/`until` a `ModeDefinition` carries: a session is what a window will one day be resolved from, which is why they are two words. In SQL never the bare word, since a Supabase _auth_ session is a third sense and `…_session_bound_writes.sql` means that one.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **session board** | The standings of one **session**, and the only standings a challenge has: one row per player per session, kept forever and reset by nothing. No today, no week, no ever — a session _is_ its own window, which is exactly why it needs none of the three. `session_scores` in the database, `sessionBoardOf` in `hooks/use-session-card.ts`, drawn by `TabPanel` like any other. **Never shortened to "board"**: a board is one mode × difficulty pairing with a reign and a place in the podium, and a session board has neither. It does now show a **place** — gold, silver or bronze on the game-over screen, drawn by `sessionMedal` with no period word beside it, since a session has one set of standings and nothing to tell them apart from. That place is settled when the window shuts and cannot be taken back, so it is not a **medal** in the losable sense this file gives the word; the player reads the same metal either way, which is the same split `host`/`admin` and `accept`/CLAIM already run on. The `board` capability is where the app asks which it means. A challenge aired twice is two session boards, the second starting empty.                                                                                                                                                                                                                                                                                             |
| **summary**       | What one closed **session** came to, told once: its three **places**, where the player themselves came, and an invitation to whatever is on next. On the first intro they reach after the window shuts, and only to somebody with a `session_scores` row on it — eligibility is that row and nothing is kept on the device to decide it. A page of the launch popup beside the winnings and the **recap**, which it is deliberately not: a recap speaks for the six scored boards over a week and to nobody in particular, where a summary speaks for one session and only to somebody who played it. At most **one** is ever told — the newest close — and the watermark moves past every older one, because a summary expires the way a recap does. Never kept, never re-opened, nothing paid. `SessionSummary` and `summaryOwed` in `lib/session-summary.ts`, `my_session_summaries` in SQL, SEEN_SUMMARY_KEY on the device. Not **results**, which is the multiplayer screen.                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| **drill**         | The fixed list of targets a **session** deals: the same values, in the same order, in the same places, for every player and every run of that session. Derived from the session's own id, so there is nothing stored and nothing an admin can set — and a rerun of the same challenge is a different drill, which is what keeps the first airing's standings meaning what they meant. Nine targets _and_ nine places: the values are a fact about the session alone, the places a fact about the session and the canvas, so two runs on one phone are identical and another display gets the same nine scattered its own way. A drilled run also ends differently — when its drill is spent and the board is clear, rather than when its lives are. `spawn.drill` on the rules, `lib/drill.ts`. Not a **lesson**, which is a script of boards with teaching over each, and not a **submode**, which is a mode with rules taken off.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **measure**       | The figure a **session board** is ordered by and its places settled on: the **score** everywhere but a race, where it is the **time**. One word per session, stamped on the row when it is booked rather than passed into each read — which is what lets the intro's card name the _fastest_ player on a race, since it answers for every open session at once and has no argument to take. The server still knows nothing about modes; it is told, exactly as it is told a session score's difficulty. Distinct from the **headline**, which is which of the two _factors_ a run reports — and a **board** has no measure and never will, `scores` having one figure to be ordered by. `scoring.measure`, `measureOf`, `challenge_sessions.measure`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **teaser**        | The face a session's card wears before it opens: its name and the countdown to its start. Shown from the moment the session is booked, however far ahead — there is no lead time to set. `teaser` on `SessionCard`, chosen by `cardSession` in `lib/challenge-session.ts`. The `teaser_minutes` column on `challenge_sessions` and the `teaser_minutes` row in `settings` are leftovers nothing reads. Deliberately **not a lead** — `leader`, `leader_name` and the `lead_row` alias already mean the top player on a **session board**.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **closing early** | Shutting a live **session**'s window now, keeping everything behind it: the standings stand exactly as a natural close would have left them and the places settle on the spot, because a place is settled the moment its window shuts and shutting early is still shutting. **CLOSE EARLY** on the planner, `close_challenge_session_early`, `closeSessionEarly`. Built from the column it moves (`closes_at`) rather than given a word of its own, and that is how it stays clear of **cancelling** — which is spoken for: `cancel_challenge_session` deletes a booking, which is the right act for a session nobody has played and is now refused for a live one or for any row with scores behind it. The two sit one above the other on the same form, so never let them drift into one word. Cannot be undone: running the challenge again is a new session with a **session board** of its own.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **extending**     | Giving a live **session** more time: hours and minutes on the planner, one figure of minutes on the wire, added to the end. Leaves a mark — `extended_at` — which the intro's card reads to say the window moved, for the rest of that window and with no seen-state of its own. **EXTEND** on the planner, `extend_challenge_session`, `extendSession`. The third door into `closes_at` beside planning and editing, and so the third that has to go through `challenge_session_clashes`: an extension that would run into another booking of the same challenge is refused with the message the other two give. Not a **record**, a **medal**, an **achievement** or a **winning** — nothing is paid and nothing is kept.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **recap**         | What last week on the boards came to, told in two or three sentences on the first open of a new week — one page of the launch popup, never a screen and never kept. The composition is `lib/recap.ts`, the phrasings `lib/recap-lines.ts`, the facts the `weekly_recap` RPC. Seeded on the window's Monday, so a dismissed and reopened dialog says the same thing. Not a run, not a board: it speaks about the six scored boards and to nobody in particular — what a player won is the **winnings** card, one page earlier.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **takeover**      | An all-time board changing hands inside a window: whoever holds rank one on the forever board now, where they did not when the week opened. `Takeover` in `lib/recap.ts`, `kind = 'takeover'` out of the RPC. The player-facing copy calls it a _record_, because that is the word a player uses — the code may not, since a **record** here is a score crossing a bar mid-run and then gone, and the standing it actually is would be a **medal**. Same arrangement as `host`/`admin`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| **stage**         | How hard a run's fights are, as one number every figure in both of them is read off: how often a road has men on it, how many men or towers there are, how many hits a tower stands for, and how fast anyone walks. Stage **one** is the first and easiest and is the only one there is today — `FIRST_STAGE`, `STAGE_FULL` and `byStage` in `lib/arcade-stage.ts`, and the two ends of every ramp as `*_ONE` and `*_FULL` pairs in `constants/siege.ts` and `constants/ambush.ts`. Advancing one is the part not built: a stage will last a few crossroads, and the three places that name `FIRST_STAGE` today (`openCrossroad`, and the `newSiege` and `newAmbush` calls in `hooks/use-arcade-run.ts`) are where the run's own stage goes instead. Deliberately **not depth**, which both fights used to ramp over — the only way to make a first wall gentle was to make a deep one gentle too, which is why the crossroad clock still counts depth and nothing else does. Nothing to do with the seven **stages** of the development cycle below, which are process rather than play, and not a **difficulty**: arcade has no rung to pick.                                                                                                                                                                                                                                                                                                               |
| **satiety**       | How fed the hero is on an arcade run, nought to one: full at dawn, spent a bite per way walked, and filled only by taking a walled village. A bite is smallest on a way answered in par presses and twice that with the accuracy gone out of it, on the same curve a hit is scored by. Drawn as **five loaves** beside the hearts — a scored country boule apiece, drawn by hand like every other mark this mode makes — which is the count a bite divides into: half a loaf a leg at par and a whole one at worst, so five is ten careful walks or five careless ones. They step colour twice on the way down — one loaf left, then half of one (`SATIETY_LOW` and `SATIETY_DIRE`, drawn in `SATIETY_INK`) — and neither band spends anything, both being warnings and nothing else. At nought the hero is **starving** — the empty row pulsing on top of the red it already turned, and a heart going every five seconds — which does not stop the run, the clock or the dial. Arcade's alone: it runs on its own engine, so nothing in `modes/` has heard of it. `machines/satiety.ts`, `satiety` on the arcade run, `components/game/satiety-loaves.tsx` on screen. **No label**: the loaves say food on their own, where the bar they replaced needed SATIETY written over it, so the word is now only the row's accessible name (Czech _sytost_). Not a **life** and not a **score** — it is what spends the first and arcade keeps none of the second. |
| **ambush**        | A fight on a way rather than at a place: a band of **bandits** standing on a road — three of them at the first **stage** and nine at the last — sprung partway along a walk and fought where the hero was stopped. A way that has one is **ambushed** — never "held", which already means a player holding a board, a creep that has stopped, and the time a pause took. One bandit reaching the hero costs a heart and **drives** it back to the crossroad it set off from; cutting the last one down clears the road for the rest of the run and pays a **spoil**. `machines/ambush.ts`, `ambushed` and `cutDown` on a `Crossroad`, the phases `springing` / `ambush` / `cleared` / `driven`. Distinct from a **siege**, which is a fight at a place, entered on arrival and announced by the walls it belongs to — an ambush is announced by nothing the first time, and by crossed sabres on the fan every time after.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **bandit**        | One of the men on an ambushed road: a number, a bearing and a pace. The band is whole from the first frame and nobody is reinforced, and each man takes a single hit — which is most of what makes a road different from a wall, where men arrive in ones and twos and a tower stands for several. Drawn by the same hand a **warrior** is (`SiegeSoldier`): what tells the two fights apart is the ring round the hero, not the figure in it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **spoil**         | What clearing an ambush pays, once: food (a third of the bar), a heart, or nothing — rolled from the road's own seed, so a road always pays what that road pays. `Spoil` and `spoilOf` in `machines/ambush.ts`. Not a **record**, a **medal** or an **achievement**, all three of which are things a player keeps or holds, and not a **winning**, which is gold out of a closed window: a spoil never leaves the run and is never shown on a card.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **submode**       | A run of a mode with some of its rules taken off, under a name of its own. The **tutorial** is the only one: `Submode` in `modes/types.ts`, the patch itself in `modes/definitions/tutorial.ts`. A second one is a new value there, not another boolean.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| **feature**       | One part of the app kept behind a key the code holds a guard for — usually because it is not for everyone yet, and sometimes because it has only just become so. `constants/features.ts` is the whole of what the code knows — the list of keys, and nothing about who reaches them. Who reaches them is rows: a role's **stack**, a person's **overrides** on top of it, and the feature's own **visibility**, all resolved by `effective_features` in SQL and asked for once per launch. `useFlag('x')` is how a screen asks. Formerly **flag**, which named a build-time switch; the identifiers still say flag and are renamed separately.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **stack**         | The set of features a role opens. A role _is_ its stack plus a name; there is nothing else to a role. `role_features` in the database, the ROLES tab on the admin screen. Plain on or off — the third state belongs to an override, not to a stack.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **override**      | One person's departure from their role's stack, in either direction: granted puts a feature on that the role does not give, revoked takes one away that it does. No row at all is the third state and the usual one — _inherit_. **Reset** deletes a person's override rows, returning them to the stack. `user_features`, and the tri-state rows on the admin screen's person view.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| **visibility**    | How far out a **feature** has got, as one of three words on its own row rather than a switch with two positions: **hidden** reaches nobody whatever any stack or override says, **private** reaches whoever their role or their override says, **public** reaches everybody, role or no role. Was `features.active`, a boolean — off is now hidden and on is now private, and public is the position that was missing: shipping a feature to players used to mean putting it in every stack and then carrying it there forever. Public beats the stack **and** every override — nothing can take it from anyone, so the admin screens do not list a public feature on a role or a person at all. `features.visibility`, `Visibility` in `lib/features.ts`, the three-position pill on the FEATURES tab. The `admin` key is pinned to private by a check constraint, in both directions.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| **role preview**  | An admin wearing another **role** to see what its **stack** came to: the app redrawn with that role's features, and a badge in the corner naming it. A **view, not a grant** — it moves the set `FlagsProvider` is fed and nothing else, and every write is still guarded on the server against the caller's own row, so previewing `admin` opens no button that works. Wears a stack and nobody's **overrides**, which is why it is a preview of a role and never of a person. _NONE_ on the pills is an ordinary player with no role, and the badge calls the same thing _NO ROLE_. Memory only: the badge is the way out, because a preview of a role without `admin` takes away the link that started it, and a reload is the way out of the way out. `hooks/use-role-preview.ts`, `features_as_role` in SQL, the `rolePreview` feature.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **address**       | The email a profile can be reached at, and the only thing in the app that outlives the device. One per profile, given once: **pending** from the moment it is typed until the six-digit code is, **confirmed** after — and only a confirmed one can bring a profile anywhere. Lives in `auth.users`, never in `profiles`: the confirmed one in the `email` column, the pending one in **`email_change`** — which the JS client surfaces under the different name `new_email`, so the column and the field are not called the same thing; `email` and `pendingEmail` on `use-supabase-auth`. The one piece of a player that is not public data about them, which is why it is on their own card and nowhere else.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| **restore**       | Bringing a profile onto this device from its address. A **move**, not a copy — the phone it was on loses it, by `signOut({ scope: 'others' })` from the one it arrives at — so the verb is always _moves_ and never _syncs_ or _copies_. The player reads the same word everywhere the act is named — though not on the code card's button, which says SUBMIT: RESTORE PROFILE was wider than the half-row it had, and the paragraph above it names the act already. `restoreProfile` in `hooks/use-supabase-auth.ts`, the rules in `lib/account-email.ts`, the keys it wipes in `lib/local-reset.ts`. Careful with the filename `…_profile_read_restore.sql`, which uses the word for putting three dropped columns back and has nothing to do with this.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **account**       | The `auth.users` row under a profile. A code word and never shown — a player has a **profile**, and every button says so. The two differ in exactly one way worth naming: an account starts **anonymous** and becomes permanent the moment an address on it is confirmed. Unrelated to both the other `admin`s, and the word must not start being used for either.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **tilt**          | How far the arcade map lies away from the reader, and so how much smaller and closer together whatever is further up it is drawn. A horizon stands a fixed way above the row the hero is on, and every mark is placed and sized by where it falls between the two — one number doing all three, because in a perspective size, spacing and the pull towards the centre line are one fact. A mark is never distorted, only placed and sized; a **way** is the exception, having both of its ends placed, so one running up the sheet is drawn short enough to still meet its town. Nought during a siege, which is a view of its own. `lib/arcade-tilt.ts`, `Sheet` and `tiltedAt`, `tilt` on the camera. Not the **turn**, which is which way up the sheet is read, and nothing a mode outside arcade has heard of.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |

Three words for three different rewards, and they are not interchangeable:

| Term            | What it is                                                                                                                                                                                                                                                                                                                                | Code                                               |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| **record**      | A score crossing a bar, announced mid-run and then gone. A moment, not a thing you keep.                                                                                                                                                                                                                                                  | `crossedRecords` in `lib/announcements.ts`         |
| **medal**       | A podium standing on a board. **Losable** — a rival can take it back tomorrow.                                                                                                                                                                                                                                                            | `lib/medals.ts`, `hooks/use-my-medals.ts`          |
| **achievement** | Permanent, achieved once, never lost, measured against the player's own history rather than against anyone else. _Achieved_ / _unlocked_, never _earned_ and never _won_. Code and the `achievements.earned_at` column still say "earned" — that is a shipped DB column, and renaming it would be a migration for no player-visible gain. | `constants/achievements.ts`, `lib/achievements.ts` |

An achievement's colour is the green nothing else uses (`ACHIEVEMENT_SCALE`), and that is the distinction it draws: gold is a record you currently **hold**, green is one you **keep**.

## Rules

- **Never deploy to production.** Nothing deploys on its own — a push to `main` runs the static checks (`.github/workflows/checks.yml`) and nothing else; both deploy workflows are manual-only. Do not run `gh workflow run deploy.yml`, `eas workflow:run .eas/workflows/deploy.yml`, `eas deploy --prod`, or otherwise promote to prod unless the user explicitly asks for a deploy in the current turn. "Continue", "ship it", or prior approvals do NOT authorize a prod deploy — wait for the explicit instruction every time. The **`deploy`** skill owns the procedure. A deploy goes through GitHub Actions, which runs the suite and `pnpm audit` and only then creates the EAS run; the EAS workflow on its own is an ungated bypass.

- **Never use Claude-in-Chrome browser automation without explicit agreement.** Do not launch the `claude-in-chrome` skill or call any `mcp__claude-in-chrome__*` tool unless the user has agreed to it in the current turn. Ask first.

- **Extract every string you write.** New copy is not shipped by writing it — run `pnpm i18n:extract` and translate it into Czech. A production build strips the English out of the descriptor, so a message missing from the catalog does not fall back the way it does in dev: it puts its generated id, `trdBEB`, on the player's screen. `pnpm i18n:verify` is the gate.

- **Keep the How to Play guide current.** At the end of every task, check whether the change touched gameplay — controls, targets/timers, modes, difficulty, scoring, streaks, or lives. If so, update the guide (`components/overlays/how-to-play-overlay.tsx`) so it stays accurate. The **`review`** stage of the cycle is where this check lands for work that came through it.

- **Sweep a shared style before changing it.** A size, colour, radius or spacing in this app is almost never in one place, so changing it where you found it is how the app came to have three sizes of the same primary button. Resolve the style to its owner (`constants/typography.ts`, `constants/colors.ts`, `global.css`), grep every occurrence of the owner _and_ the raw value, **list them for the user and ask before applying**, then change it in the owner once — never across the call sites. A sweep that touches eleven screens is the user's decision, not yours. The **`design-guide`** skill owns the procedure.

- **Never pick a text size by hand.** Type is a set of named roles in `constants/typography.ts` — `TYPE.button`, `TYPE.label`, `TYPE.prose`, plus `READOUT` for DSEG7 digits and `GLYPH` for emoji. A screen asks for a role; it does not choose a size, a weight or a tracking, and it does not override one field of a role. If no role fits, add one there and agree it first. ESLint reports raw `text-[Npx]` and `tracking-[Npx]` under `app/` and `components/`.

- **Extend a component, don't fork one.** Never add a second dialog, button, card or row when one already does the job — a copy does not read as a copy, it reads as a drifted original. A dialog is `ModalCard` (`CardModal` only when a keyboard sits under it); a screen is `Screen`/`ScreenLayer`; a run's last screen is `RunScreen`; a primary button is `PrimaryButton`; a link or quiet way out (CLOSE, NOT NOW) is `LinkButton`. Check the inventory before drawing anything pressable — never copy the markup from a neighbouring file, which may be one of the drifted originals. If something is close, give it a prop and comment which caller asked for it. `design-guide`'s `references/components.md` is the inventory.

## Development cycle

Work worth a document goes through seven stages, one skill each, and they **chain**: each one finishes by invoking the next, backwards included (a failed `verify` runs `build`, which runs `verify` again). A question a stage would ask goes first to the **`sdlc-advisor`** agent (`.claude/agents/sdlc-advisor.md`), which answers it from the spec, this file, memory and the repo — the user is stopped only for what it hands back, and always for production writes and the deploy:

```
brainstorm → shape → spec → build → verify → review → ship
```

| Stage           | Skill        | Produces                                                              |
| --------------- | ------------ | --------------------------------------------------------------------- |
| **brainstorm**  | `brainstorm` | Costed directions for an itch. Decides nothing. Optional.             |
| **shape**       | `shape`      | The appetite, the boundary, the rabbit holes, and the **track**.      |
| **spec**        | `spec`       | The contract: domain words, files, data, gates, acceptance criteria.  |
| **build**       | `build`      | The code, task by task, against those criteria.                       |
| **verify**      | `verify`     | A pass or fail per criterion. Hands **backwards** on a failure.       |
| **code review** | `review`     | `/code-review`, `simplify`, and the house pass. Also hands backwards. |
| **ship**        | `ship`       | Commit, branch + PR or `main`, and the offer to **`deploy`**.         |

The state lives on disk — `docs/work/<date>-<slug>/spec.md` and `plan.md` — so any stage can be run in a session that knows nothing about the ones before it. `.claude/skills/sdlc/PROTOCOL.md` owns that format; **`sdlc`** is the status board (`/sdlc`) and the dispatcher for work whose stage isn't obvious.

Two escape hatches, both deliberate. `shape` can put an evening's work on the **small** track — shape → build → verify → ship, no spec and no plan file. And a one-line fix skips the cycle entirely: fix it, **`check`**, **`commit`**. Seven stages over a typo is how a process stops being used.

## Architecture

**Expo Router (file-based routing)** — the `app/` directory defines all routes. `app/_layout.tsx` is the root layout wrapping everything in a `ThemeProvider`. `app/(tabs)/` defines the tab group; its `_layout.tsx` configures the bottom tab navigator.

**Theme system** — one colour scheme, and no switch. Semantic tokens live in `global.css` as a single `@theme` block; `userInterfaceStyle: "light"` in `app.json` pins the platform to it so nothing underneath renders against a scheme the tokens do not describe. A colour a class cannot reach — an icon's `color` prop, a worklet interpolating two inks — comes from `constants/colors.ts`, where `DIM_INK` and `MUTED_INK` mirror their tokens.

**Styling** — NativeWind v5 (Tailwind for React Native). Use `className` for static styles; the `style` prop only for values computed at runtime (dynamic colors, pixel sizes).

**Colors, typography, motion** — the three color scales (game / mode / CTA), theme tokens and contrast rules live in the **`design-guide`** skill. Consult it before picking any color the player sees.

**Modes** — `modes/` is a package, not a table. One file per mode in `modes/definitions/`, each written as the difference from one base set of rules; `modes/registry.ts` collects them and is the only thing that knows how many there are; `modes/rules.ts` resolves a mode × difficulty × submode into the `RunRules` everything else reads. Nothing outside `modes/` branches on a mode's name — it asks the rules, or `traitsOf`. Adding a mode is one file in `definitions/` plus one entry in the registry's tuple; adding a **challenge** is one entry in `modes/challenges/catalog.ts` — the **`challenge`** skill walks that entry's six decisions and owns the defaults.

**State machines** — XState v5 + `@xstate/react`. Game logic lives in `machines/game.ts`, which is the engine for every `engine: 'targets'` mode and names none of them; scoring and the route DP in `machines/scoring.ts`, both parameterised by the run's dial. Arcade is the one mode on another engine (`machines/arcade.ts`, `hooks/use-arcade-run.ts`). Components consume the machine via `useMachine` in `app/(tabs)/index.tsx`.

**Persistence** — `@react-native-async-storage/async-storage`. Thin hook wrappers in `hooks/use-persisted-*.ts` hydrate the machine on mount and write back on change.

**Animations** — `react-native-reanimated` v4 with worklets. Use `useSharedValue`, `useAnimatedStyle`, and the `withTiming`/`withSpring`/`withRepeat` drivers. Define animated sub-components at **module level** (not inside render functions) to avoid remounts.

**Platform-specific files** — Expo resolves `.ios.tsx` / `.web.ts` variants automatically. Currently used for `lib/supabase.web.ts`.

**Path alias** — `@/*` maps to the repo root (e.g. `import { mono } from '@/constants/theme'`). Never use relative `../` imports.

**New Architecture & React Compiler** — both are enabled in `app.json`.
